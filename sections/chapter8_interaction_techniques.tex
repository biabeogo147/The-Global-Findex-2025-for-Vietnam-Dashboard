\section{Chapter 8: Interaction Techniques}
\label{sec:chapter8-interaction-techniques}

\subsection{Techniques / Principles Applied}

\begin{itemize}[leftmargin=*]
\item Overview first, then filter, then details-on-demand.
\item Coordinated views that update several visuals from the same selection.
\item Power BI slicers and linked visuals as the main dashboard interaction
tools.
\end{itemize}

\subsection{How Applied in the Dashboard}

\subsubsection{Overview First, Then Filter, Then Details-on-Demand}

\dashboardfigure{0.92}{fig-page3-filter-bar.png}
{List of filters on the Account Ownership \& Access Landscape page.}
{fig:interaction-page3-filter-bar}

The dashboard was built in Power BI and uses interaction mainly to extend a
guided policy narrative into subgroup exploration. Users first see overview
states on pages such as Account Ownership \& Access Landscape and Financial
Health \& Resilience, then narrow the analysis through slicers, and finally use
details-on-demand in the live dashboard to inspect exact values. The overview
state is visible in \figref{fig:page3-interaction-states}{Page 3 default account-access state}, while the
presence of the slicer controls is visible in
\figref{fig:interaction-page3-filter-bar}{Page 3 filter controls}.

\subsubsection{Coordinated Views That Update from One Selection}

\figref{fig:interaction-page3-filter-bar}{Page 3 filter controls} shows the
main interaction design
on Page 3: the page starts with a national overview, then lets users filter by
urbanicity, income group, gender, education level, and workforce status.
Within the live Power BI dashboard, those slicers coordinate the views in
\figref{fig:account-kpi-cards}{Page 3 KPI cards},
\figref{fig:account-composition-flow}{Account composition flow}, and
\figref{fig:exclusion-friction-log}{Exclusion friction log} so that all three
reflect the same selected cohort.

\figref{fig:page3-subgroup-state}{Page 3 filtered subgroup state} provides
direct evidence that coordinated
updates occur on Page 3 after a subgroup selection. When the dashboard is
filtered to Rural + Female + Poorest 20\%, the KPI cards update to Banking
Inclusion \(41.19\%\), Financial Institution Account \(41.19\%\), Mobile Money
Account \(20.83\%\), and Digital Account \(29.49\%\). The same filtered view
also reduces the income-gender chart to the selected subgroup and rebalances
the Sankey and exclusion-barrier views to the same cohort, which is exactly the
behavior expected from linked Power BI visuals.

\subsubsection{Power BI Slicers and Linked Visuals}

\dashboardfigure{0.86}{fig-page5-filter-bar.png}
{Filter controls on the Financial Health \& Resilience page.}
{fig:page5-filter-bar}

The main interaction tool is Power BI itself, not LaTeX. LaTeX only documents
the dashboard through static figures, while Power BI provides the slicers,
linked visuals, and details-on-demand behavior described in this chapter. The
figures therefore demonstrate interaction design intent and control placement.
\figref{fig:page5-filter-bar}{Page 5 filter controls} shows that the resilience
page uses the same embedded Power BI slicer pattern already visible in
\figref{fig:interaction-page3-filter-bar}{Page 3 filter controls}.

\dashboardfigure{0.72}{fig-page3-hover-tooltip.png}
{Hover tooltip on the Page 3 Sankey flow.}
{fig:page3-hover-tooltip}

\figref{fig:page3-hover-tooltip}{Page 3 hover tooltip} then confirms a true
details-on-demand behavior on Page 3: hovering over a Sankey branch reveals the
context fields \textit{Location = Rural}, \textit{Account Ecosystem Type =
Traditional Bank Only}, and \textit{Total Weighted Population = 12}. That is
stronger evidence than a static export alone, because it shows that the live
dashboard exposes exact values and category context interactively.

\subsection{Notes / Adjustments}

The available evidence now goes beyond the static PDF because the report
includes a verified filtered state in \figref{fig:page3-subgroup-state}{Page 3 filtered subgroup state},
a verified hover tooltip in \figref{fig:page3-hover-tooltip}{Page 3 hover tooltip},
and an additional slicer screenshot in \figref{fig:page5-filter-bar}{Page 5 filter controls}.
However, the report still does not verify zoom behavior, animation, or
equivalent live interaction evidence for every other page. The chapter
therefore makes direct claims only where screenshots show the interaction
explicitly, and keeps the remaining interaction language appropriately bounded.
